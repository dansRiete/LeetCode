# 13.11 — Spring Application Events

## Questions & Answers

### In Spring, when would you choose @TransactionalEventListener over a regular @EventListener for publishing domain events?

**Your Answer (session):**
*Never used it.* ✗

**Complete Answer:**
You use `@TransactionalEventListener` when your event causes a side-effect (like sending an email, calling an external API, or publishing a Kafka message), and you ONLY want that side-effect to happen if the database transaction successfully commits.

By default, `@TransactionalEventListener` listens to the `AFTER_COMMIT` phase of the current transaction.

**The Disaster Scenario with a regular `@EventListener`:**
1. You save a `User` to the database (inside `@Transactional`).
2. You publish a `UserCreatedEvent`.
3. A regular `@EventListener` catches it immediately and sends a "Welcome!" email to the user.
4. *Seconds later*, the database throws a constraint violation and the transaction **Rolls Back**. The user was never actually saved to the DB.
5. Result: You just sent a Welcome email to a user that doesn't exist in your system!

If you used `@TransactionalEventListener`, Spring would pause the event listener and wait for the database commit to successfully finish before triggering the email logic.
