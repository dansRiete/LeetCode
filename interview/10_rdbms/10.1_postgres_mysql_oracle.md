# 10.1 — RDBMS Choice: PostgreSQL vs MySQL vs Oracle

## Questions Covered
- What are the advantages of PostgreSQL over MySQL and Oracle?
- What are the advantages of MySQL?
- What are the advantages of Oracle?
- When would you choose each?

## Complete Answer

### Quick Decision Matrix

| Criterion | PostgreSQL | MySQL | Oracle |
|-----------|-----------|-------|--------|
| License | Open source (MIT-like) | Open source / commercial | Commercial |
| Best for | Complex queries, data integrity, extensibility | High-read web workloads, simplicity | Enterprise, HA, large-scale OLTP |
| JSON support | First-class (JSONB with indexing) | Basic (JSON type, limited indexing) | Good (but verbose) |
| MVCC | Yes (always) | Yes (InnoDB only) | Yes |
| Window functions / CTEs | Full support | Full since 8.0 | Full support |
| Cost | Free | Free (Community) / paid (Enterprise) | Expensive |

---

### PostgreSQL — Advantages

**Standards compliance and correctness**
- Most SQL-standard-compliant open-source DB. Correct `NULL` handling, proper outer join semantics, full `CHECK` constraints.
- Enforces constraints strictly by default — no silent truncation, no silent type coercion.

**Rich data types**
- Native `JSONB` (binary JSON) with GIN indexes — fast key/value lookups inside JSON documents.
- Arrays, `hstore`, `uuid`, `inet`, `range` types, composite types, custom types via `CREATE TYPE`.
- `PostGIS` extension adds geospatial queries.

**Extensibility**
- Extension ecosystem: `pg_trgm` (trigram search), `pgcrypto`, `TimescaleDB` (time series), `Citus` (sharding).
- Write custom functions in PL/pgSQL, Python, Go, JavaScript.

**Advanced query features**
- Materialized views with `REFRESH MATERIALIZED VIEW CONCURRENTLY`.
- `LATERAL` joins, recursive CTEs, `DISTINCT ON`, `RETURNING` clause.
- Partial indexes, expression indexes, covering indexes.

**Concurrency**
- True MVCC: readers never block writers, writers never block readers.
- `SELECT FOR UPDATE SKIP LOCKED` — clean pattern for job-queue tables.

**Best when:** complex analytics, multi-model data (relational + JSON + geo), strict data integrity, open-source requirement.

---

### MySQL — Advantages

**Speed on simple read workloads**
- Extremely fast for `SELECT` on indexed columns — low overhead per query, light connection setup.
- Very efficient for simple `INSERT/UPDATE` in OLTP with InnoDB.

**Ubiquity and operational maturity**
- Default DB for the LAMP stack, most SaaS platforms, most hosting providers.
- Huge pool of DBAs, tooling (Percona Toolkit, mydumper), cloud managed options (RDS, Cloud SQL, Aurora).

**Replication simplicity**
- Binary log replication is battle-tested. Easy to set up read replicas.
- MySQL Group Replication / InnoDB Cluster for multi-primary HA.

**Aurora compatibility**
- AWS Aurora MySQL is a drop-in replacement with up to 5× throughput and automatic storage scaling — a common reason to start with MySQL.

**Lower resource footprint**
- Lighter memory and CPU usage vs PostgreSQL under simple workloads.

**Best when:** read-heavy web apps, standard CRUD, team already knows MySQL, AWS Aurora is target deployment.

---

### Oracle — Advantages

**Enterprise HA: Real Application Clusters (RAC)**
- Multiple nodes share a single database — true active-active clustering with no data split.
- Transparent Application Failover (TAF) reconnects clients automatically on node failure.

**Optimizer maturity**
- Cost-based optimizer with decades of tuning, statistics histograms, adaptive query plans.
- `EXPLAIN PLAN`, SQL Tuning Advisor, Automatic Workload Repository (AWR) for deep performance analysis.

**Partitioning**
- Range, list, hash, composite partitioning. Partition pruning dramatically speeds large-table queries.
- Interval partitioning auto-creates new partitions.

**PL/SQL**
- Mature procedural language with packages, bulk operations (`BULK COLLECT`, `FORALL`), autonomous transactions.

**Advanced features**
- Flashback Query / Flashback Table — query or restore to a point in time without restoring a backup.
- Database Vault, Label Security, TDE (Transparent Data Encryption) built in.
- Online DDL with minimal locking (e.g., add column without table lock).

**Compliance and auditing**
- Fine-grained auditing, Unified Auditing — common requirement in banking, insurance, government.

**Best when:** large enterprise, existing Oracle footprint, RAC HA requirement, strict compliance, team has Oracle DBA expertise.

---

### Interview Sound Bites

**"Why not Oracle if budget is not the constraint?"**
> Oracle RAC is the gold standard for active-active HA and the optimizer is unmatched, but PostgreSQL has closed the gap significantly and at zero license cost. For a greenfield project I'd choose Postgres unless I specifically needed RAC or had an existing Oracle estate.

**"PostgreSQL vs MySQL for a new microservice?"**
> PostgreSQL — stricter correctness, better JSON support, richer index types. MySQL only wins if I need Aurora or the team is deep MySQL.

**"When would you never use MySQL?"**
> Complex analytics, heavy use of window functions on large data sets, or when you need JSONB-style document queries — Postgres is significantly better there.
