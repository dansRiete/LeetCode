# 9.5 — Microservice Architecture Best Practices

## Questions & Answers

### If you need to update user data in one microservice and another user's data in a second microservice via HTTP, what would your approach be to guarantee consistency?

**The Saga Pattern.** 
You cannot use standard SQL transactions across two different microservices. To guarantee consistency when a process spans multiple services, you must use a **Saga**.

**Key points:**
- **Local Transactions:** Each service updates its own database in a local transaction.
- **Triggering:** After the first service updates its DB, it triggers the second service (via HTTP).
- **Compensating Transactions (The Crucial Part):** If the second service fails (e.g., HTTP timeout or business error), the first service must execute a *compensating transaction* to explicitly undo the first update.
- **Idempotency:** Because HTTP calls can timeout even if they succeed on the server, the second service *must* have an Idempotency Key so the first service can safely retry the request without double-updating.
